# 画面稳定性诊断（Canvas / WebGL）

## 何时用

用户描述的是**帧与帧之间的不连续**，而不是某一帧画错了：

- 「抽搐」「一跳一跳」「抖」「闪」「不稳」「像在痉挛」
- 「拖某个滑杆时画面变形 / 画面整体缩放了一下 / 上下跳了一下」
- 「线带出来之后就不动了」「动画卡一下」
- 新加了「自适应缩放 / 自适应增益 / 自适应 LOD」之后出现上述症状

**不要**用肉眼看、也不要直接改代码猜。这类问题每一帧的取值都是「正确」的，
错的是帧间连续性 —— 必须先把症状量成数字。

## 第一步（必做）：写一个稳定性核对工具

不要写一次性脚本。写一个**留下的工具**（如 `tools/<feature>-stability.mjs`），
后面每次改动都拿它做前后对照。它必须满足四条：

1. **复刻真实的渲染决策链**，而不是复刻一份简化版算法。
   顺序通常是：原始数据 → 特征/包络 → 尺度（缩放/增益/区间）→ 基线/偏移 → 像素坐标。
   **尺度决策这类逻辑要抽到一个独立模块（能同时被渲染层和工具 import），
   工具只负责复刻「缓存与调用时机」**。
   > 真实踩过的坑：工具自带一份旧算法副本，于是工具说「换挡 10 次」、
   > 屏幕上跑的是另一套规则，两者完全对不上。
2. **探针必须固定「绝对时刻/绝对坐标」且密铺整个窗口。**
   不要让探针跟着滚动窗口一起走 —— 那比的是「不同时刻的数据」，
   本来就不该相同，量出来的是噪声。
   > 真实踩过的坑：只放 5 个固定探针，相位任意，正好全落在平坦段，
   > 量出「抖动 0.02px」的假好消息。48 个探针才覆盖到尖峰陡沿。
3. **报最差值，不要只报中位数。** 中位数永远是 0.001px，问题全在最差值里。
   同时报「超标帧占比」（如 >0.5px 的帧有多少）。
4. **诊断工具自己的口径要先自查一遍。** 典型失效点：
   - 探针落到窗口外 → 被钳到端点，量到的是「没画出来」而不是「被改写」
   - 倒置/负向的波形按「最大值」取极值 → 量到恒为 0，变异系数全是数值噪声
   - 返回的是「窗口 ÷ 段数」而非推导出的名义值 → 断言「与窗口无关」时误判

## 第二步：五类指标，逐个量

| 指标 | 怎么量 | 阈值 |
|---|---|---|
| **采样密度** | 采样步长 / 步长相对最窄特征的比 | 步长必须**不是恒定值**（见下） |
| **纵向稳定性** | 逐帧的尺度挡位与基线位置 | 挡位切换 0 次；基线跳动 <1px |
| **历史冻结度** | 改参数后，在**同样的绝对时刻**重新取值，比较差值 | 改写 <2% 的信号幅值 |
| **逐搏/逐周期一致性** | 同一种周期反复出现时各极值的**变异系数** | CV <2% |
| **逐帧像素抖动** | 同一绝对时刻的纵坐标逐帧差 | 最大 <0.5px（肉眼不可见） |

改完之后必须能给出**前后对照的数字**，而不是「感觉好多了」。

## 四类根因（按出现频率排序）

### 1. 量纲错误被 clamp 悄悄吃掉
```js
const wPx = wSec * pxPerSec;              // 秒 × 像素/秒 = 像素
const step = clamp(wPx / 2.2, 0.004, 0.02);  // 却当「秒」用 → 永远撞上限
```
看着有上下界、很安全，实际**推导结果恒为常数**，「自适应」名存实亡，而且不报错。
**凡是「由某个量推导尺度/步长/密度」的地方，都要断言推导结果不是恒定值。**

量纲错了一般的修法：先写出目标（如「折线插值误差 ≤ 亚像素」），
再反推公式。例：尖峰处二阶导 ≈ 2·A/w²，线性插值误差 ≈ step²·A/(8w²)
→ step ≲ 0.7·w（w 为特征宽度）。

### 2. 极值点没被采到 → 逐周期形态随机
窄尖峰（宽度只有几个采样步）的极值是否能采到，纯看格点相位；
相位随窗口滚动而变，于是**每一个周期的峰高/谷深都不同** —— 看起来就在抽。
**修法：把每个周期的极值时刻（尖峰、谷、拐点）直接钉进采样序列**，
而不只是钉一个主峰。钉进去之后折线的极值就有了保证。

### 3. 离散挡位的自适应在边界来回换
连续输入 + 离散输出（缩放挡位、LOD、画质档）+ 每帧重算 = 边界处逐帧跳。
- 只加死区（迟滞）只能防抖；
- **必须先把输入量化成台阶**（如把包络向外取整到 0.02 单位），
  让输入本身变成分段常数，输出才真正不动。
- 死区规则：只有当前挡位确实放不下才降挡；只有上一挡还有余量（如 14%）才升挡。
- 顺手检查包络/输入的**缓存键**：键里带了一个每周期都在变的量（如瞬时周期长度），
  缓存就永远不命中，等于每帧重算。

### 4. 「画出来的历史」被「当前参数」重排
只要是历史（波形条、日志、轨迹、拖尾），就要**逐条记录它当时的参数**，
渲染时用那一条自己的参数，而不是统一用当前值。
> 真实案例：心电条只存了搏动时刻，渲染时统一用「当前 RR」→
> 拖心率滑杆时过去几秒的波形整体变形（实测改写量占信号幅值 29%）。
> 修法：每条记录存自己的 RR，新增 `makeXxxLayouts(items)` 逐条算布局。
> 语义上要区分：**已发生的历史参数要冻结，振幅类特征仍取当前值**（严重度是实时可调的）。

## 交付前

1. 把稳定性检查写进常规测试（断言 + 阈值），别只留在工具里。
2. 加一条**直接对着症状本身**的断言。例：把画布元素的**渲染像素截图两次、隔 0.5 秒比对**，
   只要内容静止就报错 —— 这比任何内部指标都更贴近用户所见。
   用截图而不是页内 `getImageData`：后者会触发 Canvas2D 性能告警，且量的是绘制指令而非最终画面。
3. 量一下性能代价（更密的采样会让每帧计算量成倍增长），给出实际毫秒数。
4. 在文档里写清「这是刻意设计」还是「缺陷」—— 例如「拖参数时过去的波形不变」
   容易被当成 bug 反复报，要在故障排查表里说明。
