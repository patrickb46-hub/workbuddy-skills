# 上传前隐私清单

## 一、绝对不能上传

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 真实姓名 / 网名与实名绑定 | 出现在 LICENSE、README、package.json author | 用 GitHub 用户名或留空 |
| 学校 / 公司 / 班级 | "XX 中学七年级"、内部项目代号 | 改成中性描述 |
| 联系方式 | 手机号、个人邮箱、微信号 | 删除 |
| 身份证 / 学号 / 住址 | — | 删除 |
| 密钥 | `ghp_…`、`sk-…`、`AKIA…`、SMTP 授权码 | **先吊销**，再改成环境变量 |
| 私钥 / 证书 | `id_rsa`、`*.pem`、`*.p12` | 删除，加进 .gitignore |
| Cookie / 会话 | `cookies.json`、`.netrc` | 删除 |
| 绝对路径 | `/Users/<你的用户名>/...`、`C:\Users\<用户名>\...` | 改成相对路径或 `~` |
| 内网地址 | `192.168.1.x`、公司 VPN 域名 | 改成占位符 |
| agent 记忆 / 会话记录 | `.workbuddy/`、`.claude/`、`.codex/`、`.agents/` | **必须**写进 .gitignore |

## 二、容易被忽略的位置

- `git log` 的历史作者信息（邮箱会公开）。首次提交前就应设好 noreply 邮箱。
- 图片 EXIF（截图里可能带设备名、路径）。需要时用 `exiftool -all= x.png` 清。
- 文档里"截图示例"的窗口标题、地址栏 URL、书签栏。
- 已删除文件仍留在历史里：`git log --all -- path` 查，必要时重建仓库。
- `.vscode/`、`.idea/` 里的本地路径。
- npm / PyPI 发布物的 `author` 字段。

## 三、判定尺度

- **CRIT / HIGH：零容忍**，必须处理或经用户逐条确认后才能推。
- **MED**（如内网 IP、示例邮箱、`localhost:3000`）：判断是否真实暴露；不确定就问。
- 文档里的占位符（`user@example.com`、`/path/to/your/project`）不算泄漏。

## 四、密钥处理铁律

1. 只要真实密钥进过任何一次提交，就视为已泄漏——**先吊销/轮换**，再谈清理历史。
2. 不要用"删掉那一行再提交"来善后：历史里还在。
3. 改写历史（`git filter-repo` / BFG）属于破坏性操作，必须用户明确同意。

## 五、收尾给用户的话

- 说明扫描了什么、命中什么、怎么处理的。
- 若有忽略项，写明"第 X 项经你确认属于公开信息，已忽略"。
- 给出仓库 URL 与提交摘要。
