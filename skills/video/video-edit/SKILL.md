# 真实素材剪辑

**和"生成型"做视频是两条路。** 那套（`bilibili-explainer`）是写稿→配音→代码画画面，
本技能是**拿到别人的实拍素材，从里面挑出能用的**。核心不是"剪"，是**先看清素材里有什么**。

## 四条铁律

1. **只读原素材**。脚本只读取，所有产物写到工程目录。永不覆盖、移动、删除源文件——那是奶奶和学校的素材。
2. **先体检，再剪**。上来就丢进剪辑软件，会被竖屏、无音轨、变帧率、超长镜头一个个绊住。
3. **先看后剪**。1 小时素材挑 3 分钟，必须先把画面变成能扫读的缩略图，人（或模型）看过再定 EDL。
4. **进 EDL 的每一段都要有理由**。`note` 字段写清"这段是干什么的"，否则剪到后面全是废片。

## 三步流水线

```
素材 → ① scan.py 体检 → ② sheet.py 抽帧 → ③ 人定镜头表 → ④ edl.py 出片
```

### ① 体检：这段素材有没有坑

```bash
python3 <skill>/scripts/scan.py "<素材目录>" -o "素材清单.md"
```

输出每段视频的时长/分辨率/帧率/体积/拍摄时间，并自动标出问题：

| 标注 | 含义 | 怎么办 |
|---|---|---|
| 旋转 N°（显示为竖屏） | 手机竖拍靠元数据翻转 | 已自动换成实际宽高，剪辑时会被 ffmpeg 自动转正 |
| 竖屏素材 | 插横屏成片会留边 | 用 `--fit blur` 模糊背景铺满，比黑边好看 |
| 无音轨 | 部分录屏/相机延时没声音 | 脚本会自动补静音轨，否则拼接会失败 |
| 长素材 | 一段超过 10 分钟 | **先拆镜头**，不要整段丢进 EDL |
| 分辨率偏低 | <720p | 上大屏会糊，优先不用或只用一小段 |

**先看合计时长**：素材 90 分钟要压成 3 分钟，意味着平均每 30 分钟只留 1 分钟——得下狠手。

### ② 抽帧：不播视频也能"看"清

```bash
# 单段：抽 12 帧拼成一张图，每格带时间码
python3 <skill>/scripts/sheet.py video.mov -n 12 -o video.sheet.jpg

# 整目录批量：每段一张
python3 <skill>/scripts/sheet.py "<素材目录>" -n 8
```

每格下方标 `[序号] 时:分:秒`，就是 EDL 里要填的时间码——**看图写清单，不用来回播**。

抽帧数怎么定：

| 素材时长 | 抽几帧 | 用途 |
|---|---|---|
| < 1 分钟 | 6–8 | 看清内容就够 |
| 1–5 分钟 | 12–15 | 挑镜头 |
| 5–20 分钟 | 16–20 | 定位段落 |
| > 20 分钟 | 先按 20 帧粗看，锁定区间再对那一段细抽 | 否则信息密度太低 |

抽完用 `ViewImage` 读图，逐格记下"这一段发生了什么"。

### ③ 定镜头表（人工确认环节）

把抽帧看到的可用片段写成 EDL。**这一步必须人过一遍**——模型判断"这个画面好看"不可靠，
但判断"这段有没有人、糊没糊、是不是重复"是可靠的。

EDL 是制表符分隔的五列（第 4 列是速度，写 1 或不填＝原速）：

```tsv
# 文件	起	止	速度	备注
~/素材/IMG_0012.mov	00:01:23	00:02:05	1	开场海面空镜
~/素材/IMG_0018.mov	12.5	20	1	奶奶在海边笑
~/素材/IMG_0031.mov	00:00:05	00:00:22	2	操作流程，二倍速压掉
~/素材/IMG_0044.mov	00:06:11	00:06:20	0.6	关键瞬间，慢放强调
```

顺序即成片顺序。时间码支持 `12.5` / `00:00:12.5` / `1:02:03`。`#` 开头是注释。
第 4 列若不是数字（比如直接写备注），会自动当成备注，兼容旧的四列格式。

### ④ 出片

```bash
# 先校验，不转码（秒回，检查文件在不在、时间码有没有越界）
python3 <skill>/scripts/edl.py check 镜头表.tsv

# 正式剪
python3 <skill>/scripts/edl.py run 镜头表.tsv -o 成片.mp4 --fit pad --lufs -16
```

## 三种调速手法，各解决一个问题

素材时长压不进目标时，**别只是硬砍掉一半内容**，先想清楚你要观众感受什么。

| 手法 | 用在哪 | 效果 |
|---|---|---|
| **掐**（只截取不改速） | 论证难度、关键结论、情绪镜头 | 最稳。信息完整，语音不断 |
| **加速 1.5–3×** | 操作流程、参数设置、铺垫过程 | 信息密度高、显"手忙脚乱"；观众知道你在展示"复杂"，不会怪你讲太快 |
| **慢放 0.5–0.7×** | 决定成败的一瞬、着舰/落点/击发 | 把一秒拉成三秒，强迫观众看清"这一步有多难" |

**一条片子的节奏公式**：慢的地方更慢，快的地方更快。全程原速最闷，全程快切最乱。
先定 1–2 个"要观众屏住呼吸"的瞬间（慢放），其余铺垫用加速压掉，剩下的才用原速。

倍速还顺带解决**原声断裂**：讲解类素材硬切会让语音"说到一半跳走"，把操作段加速后，
断点落在本来就快速切换的画面上，没人在意；但**论证段千万别加速**，那句话听不清就白讲了。

出片后 `edl.py` 会自动比对预期时长，偏差超过 5% 会警告——倍速静默失效时能立刻发现。

## 两种场景的标准参数

| | 典礼 / 大屏播放 | 家庭回顾片 | 竖屏发朋友圈 |
|---|---|---|---|
| 分辨率 | `--w 1920 --h 1080` | 1920×1080 | `--w 1080 --h 1920` |
| 帧率 | `--fps 30` | `--fps 30` | `--fps 30` |
| 画面适配 | `--fit pad`（保原比例、黑边） | `--fit blur`（模糊背景铺满） | `--fit cover`（裁切填满） |
| 响度 | `--lufs -16` | `--lufs -16` | `--lufs -14` |
| 时长 | 严格卡死，超时现场会被掐 | 3–5 分钟 | 60 秒内 |
| 转场 | **硬切**，不要花转场 | 可加淡入淡出 | 硬切 |
| 画质 | `--crf 18`（别再低） | `--crf 20`（省空间） | `--crf 20` |

**典礼片为什么用 `pad`**：投影/大屏的宽高比未必是 16:9，裁切会切掉人脸和字幕。保原比例最稳。

**为什么一定要 `--lufs -16`**：手机外放和现场扩声的动态范围差十倍。不做响度归一，
安静片段现场听不见、响的片段破音——这是学校典礼片最常见的翻车点。

## 踩过的坑

- **`-t` 必须放在 `-i` 前面**。放在后面会变成"输出时长上限"，把 `setpts` 压缩过的流又拉回原长，
  **倍速静默失效**（实测：`-t` 在 `-i` 后出片 10.0s，挪到前面 5.07s，正好一半）。脚本已修正。
- **硬切有"咔"的爆音**。切点处波形突跳，耳机里很明显。脚本每段首尾自动 25ms 淡入淡出
  （结尾用 `areverse` 翻转后再淡入，不必预先知道片段时长）。要听原汁原味的切点用 `--no-declick`。
- **变帧率（VFR）**：手机录屏/部分安卓机是 VFR，直接拼会音画不同步。脚本统一 `fps` 转 CFR 规避。
- **无音轨素材拼接失败**：concat 要求所有片段都有音轨，脚本自动补 `anullsrc` 静音。
- **`-c copy` 拼接的前提**：所有片段分辨率/帧率/编码/采样率必须完全一致，所以脚本每段都重新归一化，
  不要手动混用不同来源的文件。
- **`-ss` 放在 `-i` 前面**是快速定位（关键帧），精度到帧但极快；放后面是精确 seek 但慢。脚本用的是前者，
  对粗剪够用；如果发现切点偏几帧，把 `-ss` 挪到 `-i` 之后。
- **抽帧图别太大**：4 列 × 360px 宽 ≈ 1500px，`ViewImage` 能看清；超过 2000px 会糊。
- **素材占盘**：1 小时手机 4K 素材约 10–30 GB。开工前 `df -h` 看一眼，别剪到一半盘满。
- **广告/赞助段要主动找**。科普视频常在 1/3 处插一段产品推荐，抽帧时看到真人+横幅就要怀疑，
  把整个区间从 EDL 里排掉，否则成片里突然冒出品牌 logo。
