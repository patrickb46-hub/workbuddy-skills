# 试卷全解 ＋ 出题练习卷

两条分支共用一套视觉基调（宋体／墨黑／深红／A4 打印）。**A 全解**：照片 → 完整推导＋考点表；**B 出题**：知识点 → 练习卷（左目录＋右题面＋折叠答案）。先判分支，再动手。

## 何时用

用户给出一个或多个试卷分组文件夹，或说"我下载了照片"（默认去 `~/Downloads` 找），要求"完整解答全部题目"。也适用于练习题、学习单、小报的"给出答案+过程"类任务。

**两条分支，先分清再动手：**

| 分支 | 触发 | 有源图吗 | 产物 |
|---|---|---|---|
| **A. 全解**（主干，下文全部内容） | "解答这份卷子""全解""我下载了照片" | 有 | 全解 HTML ＋ 考点知识点 HTML |
| **B. 出题**（见下节 [出题分支](#quiz-branch)） | "出题""给我出几道题""按这个知识点出题""出一份练习卷""专项练习" | **没有** | 单份练习卷 HTML（答案折叠） |

走 B 时**跳过第 0–2 步的全部读图/定位工作**，直接从「出题分支」那节开始。

## 产物放哪里（2026-10-14 用户明确要求，最高优先级，每次都要遵守）

```bash
BASE_DIR="~/Desktop/Recently/日常作业"     # 所有产出的根目录
GROUP_DIR="$BASE_DIR/<学科>/<组名>"                     # 例：$BASE_DIR/数学/周末4
```

- **分组文件夹一律建在 `$BASE_DIR` 下**（`学科/组名/` 两层），处理期间结构是 `HEIC/`（原图副本）＋ `JPG/`（转码件）＋两份 HTML（HTML 与 `HEIC/`、`JPG/` 同级，不要塞进子目录）；**任务收尾时 `HEIC/` 会被删掉**（见工作流第 7 步），最终交付文件夹里只留 `JPG/` ＋两份 HTML。
- **源照片默认从 `~/Downloads` 找**（2026-10-18 用户明确要求）：用户说"我下载的照片"而没给路径时，按修改时间取 `~/Downloads` 里最新的 `IMG_*.HEIC/IMG_*.jpg` 等，先逐张读内容确认是什么卷再分组，不要凭文件名猜。
- 用户**直接点了路径**就以用户给的为准（例如"就放 `日常作业/数学/周末4`"），不要硬套 `学科/` 那一层。
- 源照片在别处时，**用 `cp` 复制进 `$GROUP_DIR/HEIC/`，绝不用 `mv`**（处理期间不动原图；任务收尾才按第 7 步删除 Downloads 里的源 HEIC）。
- 目录不存在就用 `mkdir -p` 建出来。
- **桌面快捷方式照旧建在 `~/Desktop`**，而且**只给「全解」那一份**。一句话总结：**产物归档进 `日常作业/`，桌面只留一个入口链接。**（不要再把 HTML 本体写到桌面。）
- 早前散落在桌面/其它位置的旧产出**不要搬动**，新任务按新规则走即可。
- **例外（出题分支 B）**：没有源照片，不建 `HEIC/`、不建 `JPG/`，目录名用 `<学科>/出题-<主题>/`，收尾也不动 `~/Downloads`。详见 [出题分支](#quiz-branch)。

## 0. 预处理：格式转换与基础图像处理（2026-10-12 新增）

**本技能自带一个本地图像工具。凡是「读不了的图」和「要裁要转的图」，一律先过它，不要现写 PIL 脚本。**
全部处理在本机完成，**不联网、不依赖外部服务、不需要 pip 装任何东西**（HEIC 走 macOS 自带的 `sips` 解码）。

### 入口（两个路径写死，照抄）

```bash
IMG_PY=python3   # 必须用它，才有 Pillow
IMG_TOOL=~/.workbuddy/skills/exam-paper-solutions/tools/imgtool.py
```

⚠️ **不要用系统 `/usr/bin/python3`**（没有 Pillow）；也**不要为了让 Pillow 读 HEIC 去装 pillow-heif**（要联网，没必要）。

### 子命令一览

| 子命令 | 干什么 | 典型调用 |
|---|---|---|
| `deps` | 报告本机引擎能力（含解码缓存状态） | `$IMG_PY $IMG_TOOL deps` |
| `prep` | **一站式**：扫描+转码+整页阅读副本+尺寸建议 | `$IMG_PY $IMG_TOOL prep "<分组文件夹>" -o /tmp/prep --human` |
| `lines` | **自动列出文字行区间**，直接给出可用的 crop 参数 | `$IMG_PY $IMG_TOOL lines a.jpg -o /tmp/l.jpg --human` |
| `grid` | **叠加百分比网格**，用来一次把坐标量准 | `$IMG_PY $IMG_TOOL grid a.jpg -o /tmp/g.jpg` |
| `strip` | 长图按高度或等份**切成多条**，一次返回 | `$IMG_PY $IMG_TOOL strip a.jpg --n 5 --max 1800` |
| `figcheck` | **数学图复检**：抽出 HTML 里每幅 SVG 单独渲染，与原题并排拼对照图 | `$IMG_PY $IMG_TOOL figcheck 全解.html --src JPG/a.jpg --map "1=0.1,0.2,0.95,0.55"` |
| `scan` | 扫目录，标出哪些**需要转码** | `$IMG_PY $IMG_TOOL scan "<分组文件夹>" -r --human` |
| `info` | 看单个文件的格式/尺寸/可否直接读 | `$IMG_PY $IMG_TOOL info a.HEIC b.jpg` |
| `readcopy` | 生成阅读副本并自动转码（默认 2000px） | `$IMG_PY $IMG_TOOL readcopy "<目录>" -o /tmp/read1 --max 2000` |
| `convert` | 批量转码（HEIC→JPG 等） | `$IMG_PY $IMG_TOOL convert "<…/HEIC>"` → 自动写到同级 `JPG/` |
| `convert --skip-readable` | 只转读不了的，本来就能读的跳过 | `$IMG_PY $IMG_TOOL convert "<…/周末4" --skip-readable` |
| `convert --force` | 幂等重跑：覆盖上次的产物 | 不加会另起 `-2` 副本，重复跑会越堆越多 |
| `crop` | 裁切（像素或比例），可顺带放大 | `$IMG_PY $IMG_TOOL crop a.jpg -o q.jpg --rel 0.03,0.26,1.0,0.32 --scale 3` |
| `crop --to-width` | 裁完全宽长条时**锁输出宽度** | `$IMG_PY $IMG_TOOL crop a.jpg -o q.jpg --rel 0,0.26,1.0,0.32 --to-width 2000` |
| `rotate` | 旋转（任意角度，自动补白底不留黑角） | `$IMG_PY $IMG_TOOL rotate a.jpg -o b.jpg --deg 2.5` |
| `resize` | 缩放 | `$IMG_PY $IMG_TOOL resize a.jpg -o c.jpg --max 2000` |
| `flip` | 水平/垂直翻转 | `$IMG_PY $IMG_TOOL flip a.jpg -o d.jpg --flip horizontal` |
| `clean` | 清理工具自建的临时工作区／解码缓存 | `$IMG_PY $IMG_TOOL clean --workspaces` |
| `gui` | 起本地图形界面（给人手动用，见文末） | `$IMG_PY $IMG_TOOL gui` |

### 找坐标：别再靠肉眼估（2026-10-12 实战教训）

**上一次做全解，12 次 crop 里有 7 次纯粹是在猜相对坐标**（找「求证」那一行连裁 3 次才对准，找几何图裁了 2 次）。
现在改成先定位再裁，顺序固定：

```bash
# ① 让它告诉你每块内容在哪（一次拿到全部行区间 + 现成的 crop 参数）
$IMG_PY $IMG_TOOL lines /tmp/prep/IMG_4155.jpg -o /tmp/l4155.jpg --human
#   # 1  y 188–318   rel 0.1253–0.212   → crop --rel 0,0.1253,1.0,0.212
#   # 2  y 378–444   rel 0.252–0.296    → crop --rel 0,0.252,1.0,0.296
#        ↑ 顺带读一眼 /tmp/l4155.jpg（红=上边界 蓝=下边界，带编号），和 JSON 对得上再动手

# ② 需要横向也定位时（如「右侧那幅几何图」），让图上带百分比刻度，直接量
$IMG_PY $IMG_TOOL grid /tmp/prep/IMG_4155.jpg -o /tmp/g.jpg
#   再 crop --rel 0.62,0.32,0.95,0.48 --scale 2
```

两条经验：

- **`lines` 的块边界经常把相邻两行文字并成一块**，这不算错（拿来放大看依然清楚）；要单行就调小 `--gap`。
- **纸面发灰或有背面透印时**，`lines` 会自动加重判定强度重试，返回里的 `abs_margin_used` 与 `tried` 会告诉你最后用了哪档。
  实测四张试卷：强度 45 时那张稀疏的几何页整页糊成 47% 高的一块，**60 才干净**（所以默认 60）。
  **默认值就是在这次任务上扫出来的**，别随手改小；看到 `count: 1` 或「最大块占半页」说明还没分开，先看 `tried`。

### 调用约定（AI 必读）

1. **默认输出一行 JSON**，先看 `ok` 字段；失败时是 `{"ok": false, "error": "…"}`，退出码 2。
2. 拿路径**直接读结果数组**，不要自己去拼路径：
   - `prep` / `readcopy` → `read_paths`（可直接交给读图工具的绝对路径，按自然序排好）
   - `convert` → `paths`（落盘后的真实路径，撞名时已自动加 `-2` 后缀）
   - `strip` → `paths`（按顺序读一遍等于整页）
   - `figcheck` → `figures[].png`（单幅重绘）、`figures[].pair`（左原题右重绘的对照图）、`sheet`（总览）
3. 加 `--human` 换成给人看的中文文本（自己调试时用），行数比 JSON 少一半。
4. **原图永远只读**：只读原文件，只写新文件；输出撞名不会覆盖，只会另起名字。
   重复转换同一批会堆出 `-2` 副本，想幂等重跑就加 `--force`。
5. 目录输入会自动下探一层（`分组文件夹` → 里面的 `HEIC/`、`JPG/` 都能找到），所以
   `prep "<分组文件夹>"` / `convert "<分组文件夹>" --skip-readable` 都能直接用，不必非得加 `-r`。
6. **临时产物统一丢进工具自建的工作区**（不写 `-o` 时自动落在系统临时目录下的 `imgtool/`，
   带 `.imgtool_workspace` 标记）。收工时 `clean --workspaces` 一键清掉，别让 `/tmp` 越堆越多。
   `clean` 有硬护栏：**只删带标记的工作区**，传别的目录会直接拒绝。
7. **`--rel` 给 0–1 的小数、`--box` 给像素**`左右,上,宽,高`。真给混了会照宽容规则处理，
   但返回值里会多一条 `warnings` 提醒你 —— 看见警告就回头改参数，别硬跑。

## 硬性交付要求（用户明确定过，不得省略）

#### 排版取法（2026-10-21 接入 frontend-design）

基础 CSS 已经定死了视觉基调（宋体、墨黑、深红强调、A4），**不要重新设计配色**。下面这几条是把 frontend-design 的"设计判断"落到试卷场景上的可执行约束，用于决定**版面怎么排**，不是换皮：

1. **层级靠字号和留白，不靠加色**。题干 `.q` 加粗、推导 `.pf` 常规、依据 `.rs` 用绿色、答案 `.final` 加框——四级已经够用。**不要**再引入新的颜色去区分"重点/次重点"，那只会让卷面变花。
2. **一页只有一个视觉焦点**。焦点永远是 `.final` 答案框。一页里出现三个以上的答案框时，考虑把这页拆成两页。
3. **留白是结构，不是浪费**。题与题之间 20px、页内边距 38px 不要压缩；宁可多分一页，也不要把推导挤成一坨。卷面读起来累，学生就不看了。
4. **对齐比装饰重要**。推导行用 `text-indent:-12px` 做悬挂缩进，让"依据"那一列视觉上对齐；表格左对齐，数字列可右对齐。不要用居中排版长文本。
5. **克制使用强调**：`--accent` 深红只给答案框和二级标题左边框；`--ok` 绿色只给括号里的依据。两者之外全是灰阶。
6. **不用阴影、不用渐变、不用圆角卡片**。只有 `.final` 那一个 3px 圆角，其余直角。理由同上：打印友好。
7. 打印样式优先于屏幕样式。任何装饰性元素都要先问一句"黑白激光打印出来还剩什么"，剩不下的就删掉。

> 判断标准很朴素：**这份卷子打印出来，学生一眼能找到答案、顺着推导能看下去，就算排版合格。**


### 几何图

用**内联 SVG** 重绘，不要贴原图。取点坐标时按真实几何关系算出来（见下"读图"），再用 `线性变换 屏幕x = ox + s*x, 屏幕y = oy − s*y` 落到 viewBox 里；关键点画实心小圆 + 斜体字母标注；辅助线用不同颜色并在图注里说明。打印友好：只用 `stroke`，不依赖外部字体。

> **画完不是结束，比完才是。** 本节只管"怎么画得像"，画完还要走一遍下面「图形复检」，逐幅跟原题对照——两件事，缺一不可。

**通用设计约束（从 diagram-design 的 `layout-budget.md` / `style-guide.md` 提炼，考试卷面尤其要守）：**

3. **结构尺寸走 4px 网格**（节点位置、间距、内边距都是 4 的倍数），字号、线宽、圆角不强制。
4. **不用阴影、不用渐变、不用圆角大卡片**。打印出来全是灰浊的，纯线框最干净。

### 图形复检（2026-10-26 用户明确要求，硬性步骤，不得跳过）

**规则：全解 HTML 里每一幅图，画完都要回头跟原题比一遍，逐幅确认无误才算画完。**

先把一件事说清楚：**"坐标算对了"不等于"图画对了"。** 第 2 步的数值自检只能证明这幅图内部自洽（三点确实共线、勾股确实成立），证明不了它和原题是同一张图。下面这四类错误，数值自检一个都抓不到：

- **拓扑错**：该连的没连、连错了端点（A 连到 C，实际该连 A 连 D）
- **标记漏**：原图刻了两组等长短线，只画了一组；直角方块画在了错的角上
- **线型错**：原图的虚线延长线被画成实线，题意就从"延长 AB 到 D"变成"D 在 AB 上"
- **方向反**：左右被镜像。面积公式、角度计算全都照样通过，图却是反的

所以这一步没有"大概看着像"这一档，只有**逐幅过**。

#### 第一步：一条命令把对照图摆出来

> **范围**：本节管的是「全解 HTML 里对应原题的几何图／函数图」。
> 考点知识点那份文件里的统计图（章节条形图、难度热力图）不对应原题，不走这套流程，
> 但同样要核对**图上数值与同页表格一致**，别让图和表各说一套。

```bash
$IMG_PY $IMG_TOOL figcheck "$GROUP_DIR/<全解>.html" \
  --src "$GROUP_DIR/JPG/IMG_4154.jpg" \
  --map "1=0.10,0.18,0.95,0.52; 2=0.08,0.55,0.98,0.92" \
  -o /tmp/figchk --human
```

- `--map` 的编号对应 HTML 里 SVG 的**出现顺序**（从 1 起）。
- 坐标是"这幅图在原题照片上的位置"，优先给比例；要给像素就写 `2=px:120,800,900,700`。
- 产出：`pair1.png`… 每张左原题右重绘，`总览.png` 是所有重绘竖排在一起（先看总览看有没有少画、比例是否离谱，再逐张看对照）。
- 同时回报三个硬指标：`字母`（图上的单字母标注）、`虚线`（虚线处数）、`墨迹`（非白像素占比）。
  **墨迹 < 0.2% 会自动报警** —— 那通常意味着线根本没画出来（典型原因：`stroke="var(--xxx)"` 而那个变量在页面里没定义）。
- 一次没配全也不怕：`--map` 少给几组，没配到的图只出单图，其余照常并排比。

#### 第二步：八项逐条对（按"最容易错"排序）

| # | 查什么 | 怎么判 | 见过的错法 |
|---|---|---|---|
| 1 | **拓扑** | 逐条线段问"这两点之间到底有没有线"，斜线与内部交点尤其要看 | 该连 AD 却连成 AC；辅助线穿过本应空白的区域 |
| 2 | **点位顺序** | 谁在谁左上/右下？点在线段**内部**还是在**延长线**上？ | D 画到 AB 外侧；中点画成三等分点 |
| 3 | **字母标注** | 两边字母集合必须**完全相等**：不漏、不多、不错位 | 漏标 D；E 标到了 F 的位置 |
| 4 | **特殊标记** | 直角小方块、等长短线（一道/两道）、等角弧、平行箭头，**数量与位置**都要对 | 原图两组等长只画一组；直角标记画错角 |
| 5 | **线型** | 实线／虚线一一对应（虚线多半是辅助线或延长线） | 延长线画成实线，条件被悄悄改掉 |
| 6 | **左右方向** | 原图不对称时专门看是否被**镜像**；文字有没有压线 | 坐标系画反、三角形整体左右翻转 |
| 7 | **图上数值** | 标注的长度、角度、坐标刻度必须与题干一致 | 题干 6 cm 图上标 5；刻度单位漏了 |
| 8 | **坐标轴／函数图** | 原点、单位长度、象限范围、开口方向、顶点、与轴交点 | x 轴 y 轴单位长度不等比（图会变形） |

#### 第三步：三句话当判据

1. **只看图、不读解析，能认出这是同一道题的图吗？** 认不出就是没复检。
2. **把原图遮住，仅凭重绘图能复述出题干的所有已知条件吗？** 不能就是漏了信息。
3. **图上有没有原题没有的东西？**（自加的辅助线、多余的字母）要么删掉，要么在图注里写明。

#### 第四步：改了就得重跑

发现问题 → 改 SVG → **再跑一次 `figcheck`**，直到每一幅都过。不要"改完觉得应该对了"就交。
**复检结论要写进最终回复**，例如："4 幅图已逐幅与原题对照：拓扑、标注、标记、线型一致"。没写这句，就等于没做。

#### 原题没给图 / 图看不清时

- **题干纯文字描述**：复检对象换成题干，逐句把条件在图上找一遍——"DE⊥AC"有没有垂直标记？"D 是 AB 中点"有没有中点标记？一个条件都不许凭空消失。
- **原题图印刷模糊**：回到原图裁块放大确认（`lines` / `grid` / `crop`），**不要按"通常这样画"去补**——那是把猜测当事实，比画错更难被发现。
- **一题多配置**（如"当点 D 在射线 AB 上"）：每种合法位置各画一幅，或明示"图为其中一种情形"，并在解析里说清其余情形。


### 考点·知识点 HTML（第二个产出文件，2026-10-04 新增）

**触发**：每次"全解"任务都默认要做，不需要用户额外提醒；用户单独说"整理考点""考什么知识点"时同样适用。

**产出约定**

- **独立文件**（不是一个 HTML 里的新章节），与全解 HTML **同目录**（即 `$BASE_DIR/<学科>/<组名>/` 根目录）。
- **命名**：复用全解的主文件名，把结尾 `全解` 换成 `考点知识点`。例：
  `八上数学《周末卷（四）》全解.html` → `八上数学《周末卷（四）》考点知识点.html`。
- **不建桌面快捷方式**（只有全解那份建符号链接）。自检时要确认桌面**没有**多出这个文件的链接。
- 同样是自包含、A4 可打印 HTML，复用上面同一套基础 CSS。

**内容要求：逐题覆盖，一道不落**

用下方 CSS 里的 `.kp-item` 一块一块排，**题号必须与全解完全一致**（含小问级别，如"第 18(2) 题"）。
每个块至少给三类信息，缺一不可：

| 类别 | 写什么 | 要求 |
|---|---|---|
| **考点** | 这道题在考什么动作/能力：**题型 + 方法** | 写成可执行的动宾短语，如"解一元二次方程——用十字相乘法因式分解""证明线段相等——构造全等三角形" |
| **知识点** | 支撑它的教材条目：定义／定理／公式／性质 | 给**准确表述**并带公式，几何定理要写全"条件 → 结论"；知识点里的关键术语用 `.kb` 加粗 |
| **易错点／技巧** | 本卷最容易丢分的那一步，或一个提速技巧 | 有则必写（用 `.kp-tip`）；确实没有就写"—"，不要编 |

补充规则：

1. **一题多问**：同一大题内各小问考点不同就**分行列**（"第 18(1) 题""第 18(2) 题"各一条）；考点相同则合并成一条并在考点里写清"第 18(1)(2)"。
2. **页面组织**：按题型分节（一、选择题／二、填空题／三、解方程／四、解答题……），节内逐题；每节末尾给一张「本节考点小结」表（考点 × 出现题号）。
3. **末尾必须给「考点分布表」**：列为 `题号 | 考点 | 对应知识点/章节 | 难度(★–★★★)`，全卷题目一行一题，可另加一列"高频考点"打 ✔。
   - **加一张图（2026-10-21 起默认做，不再只给表）**：在分布表上方配一张可视化，二选一——
     **章节 × 考点数量**用横向条形图（参考 `~/.workbuddy/skills/diagram-design/references/type-bar.md`）；
     **题号 × 难度**用热力图或矩阵（参考 `type-heatmap.md`）。图的目的只有一个：让学生一眼看出
     "这次哪块失分最集中"。图上不超过 8 个条目，超了就合并小节。
4. **英语卷同样中英对照**：考点与知识点双语（英文在上、中文在下或并列），术语给英文名，如"定语从句 attributive clause"。
5. 只写**结论性知识**，不要在这里重复解题过程；需要指路就写"过程见《…全解》第 X 页/第 X 题"。
6. 可选的收尾加分项：给一张"本卷考点结构图"，把各节考点挂到章节下。**画法用树图规范**
   （`type-tree.md`）：父节点是章节，子节点是考点，超过三层就砍层级、不要出现交叉连线；
   或退化成纯 CSS 缩进树，但保持 4px 网格与单一强调色。

**每个知识点必须配 2–3 道配套题（2026-10-31 用户明确要求，不可省）**

知识点讲完就结束，学生只会"看懂"，不会"会用"。所以每条「知识点」下面固定跟：

| 位置 | 数量 | 要求 |
|---|---|---|
| **例题** | 1–2 道 | 给**完整示范**：`【思路】` 一句话点破切入点 → `【步骤】` 逐行推导（证明题每句写依据）→ `【答案】` 加粗加框 |
| **练习** | 1–2 道 | 只给**答案或答案要点**（折叠块或页末答案区），**留出学生动手的空间**，不给过程 |
| 合计 | **每条知识点 2–3 道** | 例题 + 练习之和落在这个区间；知识点本身很单薄时取 2，主干知识点取 3 |

选题纪律（这几条最容易破）：

1. **不许与全解里的原卷题目重复**，也不许"原题改个数字"充数 —— 要换情境（换图形、换问法、正问改反问）。
2. **难度参照原卷**：例题 ≈ 原卷同知识点那道题的难度；练习可**略高半档**，但不要跳到竞赛题。
3. **只考当前这条知识点**，不要顺手把别的知识点掺进来 —— 学生刚学完这一条，掺进去就分不清是哪个不会。
4. **答案必须自己算过一遍**再写进去；几何题用文字把图形条件描述完整（点、线、垂直、平行、相等），因为这里是纯 HTML 无配图。
5. 英语卷：例题/练习题干**中英对照**，答案同样双语。

版式：例题用 `.kp-ex` 块、练习用 `.kp-practice` 块（CSS 见下），两者都缩进在所属 `.kp-item` 内，
视觉上明显从属于那条知识点，不要平铺成独立大节。

### 1. 读图（先定位，再放大）

**一步到位**：`prep` 会把 HEIC 转码 + 限宽 + 尺寸建议一次做完，返回的 `read_paths` 就是可以直接读的绝对路径。

```bash
IMG_PY=python3
IMG_TOOL=~/.workbuddy/skills/exam-paper-solutions/tools/imgtool.py

# 原图 3000px 级直接读会糊，统一缩到 2000px；HEIC 在这里被自动解码
$IMG_PY $IMG_TOOL prep "<分组文件夹>" -o /tmp/prep --human
# → 读 read_paths 通读整页；再照 files[].suggest_max 决定要不要出第二档细节图
```

**默认 2000px 起步，不要从 1500 试起。** 上一次用 1500 通读，结果小字全糊，
只好把整批用 4000 重跑一遍 —— 白跑一轮。`prep` 返回的 `suggest_max`
直接告诉你「整页通读用 overview、看小字用 detail」，照它给的值来。

细节看不清时，**先定位再裁**，别凭感觉估比例：

```bash
# ① 定位：自动列出每块文字行的区间，并给出可直接用的 crop 参数
$IMG_PY $IMG_TOOL lines /tmp/prep/IMG_4155.jpg -o /tmp/l.jpg --human

# ② 放大：拿上一步的 crop_arg 直接裁，一次到位
$IMG_PY $IMG_TOOL crop /tmp/prep/IMG_4155.jpg -o /tmp/z/q13.jpg --rel 0,0.1253,1.0,0.212 --to-width 2000

# ③ 要横向也定位（如右侧的几何图）：叠一层百分比网格，照着刻度量
$IMG_PY $IMG_TOOL grid /tmp/prep/IMG_4155.jpg -o /tmp/g.jpg
```

**放大倍数怎么给**：裁的是**全宽长条**就用 `--to-width 2000` 锁宽度；
裁的是**一个小区域**才用 `--scale 2~3`。上次不懂这个区别，对全宽条带用 `--scale 3`
得到 6000px 宽的图，读图时又被压回原尺寸 —— 白放大一场。

`--rel` 的坐标系是 **EXIF 方向摆正之后**的图（工具会自动 `exif_transpose`），
所以 `lines` / `grid` 报出来的比例可以直接喂给 `crop`，不需要换算。

页数多、或者一页内容很长时，与其反复裁，不如一次切条全读：

```bash
$IMG_PY $IMG_TOOL strip /tmp/prep/IMG_4155.jpg --n 5 --max 1800   # → paths 按顺序读一遍即整页
```

### 2. 定几何图的精确坐标

- 手机照片先用 `ImageOps.exif_transpose` 校正方向。
- 用 numpy 做**连续暗像素 run-length 检测实线**、**列/行暗像素峰值检测虚线网格**，反推顶点坐标。
- **必做数值自检**：把坐标代入面积公式（鞋带公式）、勾股、角度公式验算，确认"辅助线真的构出所要的三角形""角度对得上"。曾在欧几里得 I.47 上把辅助线误连 AL（实际 A、C、L 共线），一算即露。
- 一题多解/多种图形位置时（如"当点 D 在射线 AB 上"），**用脚本枚举所有合法配置**再决定答案个数，别漏解。示例见下。

```python
# 枚举：把所有满足条件的位置都找出来，按角度去重
for phi in np.arange(-179.9, -0.1, 0.1):
    ...        # 构造 E、D、F
    if abs(AF-BD) < 1e-6:  res.append((phi, angle))
print(sorted({round(a,4) for *_ , a in res}))   # → [22.5, 67.5]
```

> ⚠️ **坐标算准 ≠ 图画对了。** 这一步只保证图内部自洽，不保证它和原题长得一样。
> SVG 写进 HTML 之后，**必须过一遍「4B 图形复检」逐幅对照原题**，才算这张图完成。

### 3. 写文件（**必须分多次小工具调用**）

单次 Write 太长会**输出被截断**。做法：

1. `Write` 写 `<head>`（含 CSS）+ 第一部分内容 + 占位符 `<!--SPLIT-->` + `</body></html>`；
2. 之后每次 `Edit`，把 `<!--SPLIT-->\n</body>` 替换成「新内容 + `<!--SPLIT-->\n</body>`」；
3. 最后一段把 `<!--SPLIT-->` 去掉。

每次调用控制在 150–250 行以内。写完检查 div 配平：

```bash
grep -o '<div' f.html | wc -l ; grep -o '</div>' f.html | wc -l   # 两个数应相等
```

### 4. 渲染自检（4A 版面 + 4B 图形复检）

#### 4A. 版面自检（整页截图，看排版有没有塌）

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --no-sandbox \
  --hide-scrollbars --window-size=1000,6000 --screenshot=/tmp/chk.png "file:///…/全解.html"
```

**最大的坑：绝对不要加 `--user-data-dir=…`。**加了必被 kill（退出码 137 / SIGTERM，前台表现为无输出直接中断），
这是本机反复验证过的死穴（2026-10-03 两次踩到）。不加则一次成功。

其余要点：
- 视口高度可以放心给到 1000×14000，早前"≥9000 会被 kill"的说法不成立；一次截全最省事。
- 想确认有没有截断/空白，用 numpy 找内容底边：
  `a=np.array(Image.open(p).convert('L')); rows=np.where(a.min(axis=1)<200)[0]; rows.max()`
  —— 底边远小于视口高度就说明下方全是空白（正常收尾），接近视口高度则要加高重截。
- 按 1000×1300 切片 `Read` 逐屏看。
- Chrome 有时写完 PNG 后**不退出**（卡在自带 GoogleUpdater），此时若用 `run_in_background` 会一直显示 running；
  图其实已经生成，直接 `ls` 看文件即可，必要时 `pkill -f "Google Chrome --headless"` 收尾。
- 日志里 `CVDisplayLinkCreateWithCGDisplay failed` 是无害噪音，不影响出图。

#### 4B. 图形复检（数学卷必做，图一画完就做）

**先 4A 看版面（有没有溢出、空白、截断），再 4B 逐幅比图。** 版面干净不代表图画对了，这是两件事。

```bash
# ① 一条命令：抽出全部 SVG → 单独渲染 → 与原题对应裁块并排拼图
$IMG_PY $IMG_TOOL figcheck "<全解>.html" \
  --src "$GROUP_DIR/JPG/IMG_4154.jpg" \
  --map "1=0.10,0.18,0.95,0.52; 2=0.08,0.55,0.98,0.92" \
  -o /tmp/figchk --human

# ② 先看 总览.png（一眼看全：有没有少画、比例是否离谱）
# ③ 再逐张 ViewImage 看 pair*.png（左原题 / 右重绘）
# ④ 改图 → 重跑本命令 → 再看，直到每一幅都过
```

逐条打勾的标准见上面「图形复检」一节的八项表（拓扑／点位／字母／标记／线型／方向／数值／坐标轴）。
**复检结论必须写进最终回复**——写了"已逐幅对照"才算做过，没写就等于没做。

## 英语试卷专属要求：中英对照（用户 2026-10-03 明确要求）

**凡英语学科的试卷/练习，产出必须中英对照，不得只给英文。** 具体：

1. **题干**：英文原题在上，紧跟一行灰色小字中文译文（`.zh`）。
2. **选项**：逐项给英文 + 中文，并把每项的汉语意思写出来，便于排除。
3. **最终答案**：`.final` 答案框内**先英文答案、再换行给中文回译**（用 `.final .fc`，不继承边框色，字号小一号）。
4. **解析**：用中文讲，语法术语括注英文（如"使役句 have sb do sth""一般过去时被动语态 was/were + done"）。
5. **词汇/词形题**：给出"英文词形链 → 中文词义"，如 `develop 发展 → development 发展（名词） → developing 发展中的 → developed 发达的`。
6. **翻译题**：给英文译文 + 回译中文，并注明所考句型。
7. **阅读理解**：每题给英文原问 + 中文译文；答案给英文 + 中文；并引用原文依据句（英文）。
8. **答案速查表**：表内英文答案 + 简短中文（可加一列"中文"）。
9. 朗读题/语音题（如划线部分发音）要标出音标，如 `severe /sɪˈvɪə(r)/ 划线 ere 读 /ɪə/`。

样式补充（在基础 CSS 上加）：


### 版式：定死，不得重新设计

一句话：**左边一条固定目录，右边题面，每题下面挂一条可折叠的答案。**

- **起点是复制模板，不是从零写**：`cp ~/.workbuddy/skills/exam-paper-solutions/assets/quiz-template.html <目标>.html`，然后把 `<title>`、header、`<nav class="toc">`、`<main>`、`<footer>` 里的【占位】换掉、删掉示例题。
- **CSS 一行都不要改**。模板里的字号、留白、配色（宋体／墨黑 `#1a1a1a`／深红 `#8b1f1f`）已经和全解那套对齐，改一处就会两边不一致。
- **左侧目录两级**：`<h2>` 是一屏一块的大章节（`01 基础填空`），`<h3>` 是块内子分组（`（一）字音`）。目录里 `<a href="#s1">` 必须对上正文 `id="s1"`——**加了章节就补目录，别让目录和正文脱节**，这是这份模板唯一容易出错的地方。
- **正文顺序与目录顺序必须一致**，`01/02/03` 编号连续。
- 手机窄屏（<900px）目录自动收起，行为已内置，不用管。

### 答案折叠：只有一种正确写法

用模板里的 `.ans` 结构（隐藏 checkbox + label + `.ans-body`）：

```html
<div class="q"><span class="idx">1.</span>题干</div>
<div class="ans">
  <input type="checkbox" id="an1">
  <label for="an1">答案与解析</label>
  <div class="ans-body">
    <span class="final">答案</span>
    <p>解析：踩分点 ＋ 易错点。</p>
  </div>
</div>
```

- `id` 必须递增唯一（`an1`、`an2`…），否则点了会连动。
- **绝对不要用 `<details>`**。这是个踩过的坑：`<details>` 关闭状态下内容由浏览器内部 slot 隐藏，`@media print` 里写 `display:block!important` **压不住**，打印出来答案整块消失。模板用的 checkbox 方案在打印时靠 `.ans-body{display:block!important}` 就能全展开，已验证有效。
- 页面右下角模板自带「展开全部答案」浮动按钮，js 已内置，不用动；打印时自动隐藏。

### 填空线的写法

用连续下划线字符 **`＿＿＿＿`**（U+FF3F 全角下划线，4 个一组）。**不要**用全角空格 `　` 拼空白——屏幕上会被折叠成普通间隙、打印出来是空白一片，学生没法往上写。

### 打印行为（已内置，无需额外处理）

目录隐藏 → 答案全部展开 → 浮动按钮隐藏 → 长表格允许跨页且表头重复 → `.ans` 允许跨页但不拆行。用户 Cmd+P 直接得到"题目+答案"的完整卷。

### 出题质量要求

1. **题量**：默认 20–30 题，按题型分 2–4 组。用户指定题量就照办。
2. **难度梯度**：基础 : 中等 : 较难 ≈ 5 : 4 : 1，由浅入深，不要一上来就压轴。
3. **每题都有答案 ＋ 解析**。解析写三样东西：**踩分点、易错点、为什么**。只给结论等于没解析。
4. **覆盖要对得上**：用户给了知识点清单/章节，就一个点至少一题；开头用一张小表写清「考点 × 题号」分布，让人一眼看出覆盖全不全。
5. **不超纲**：用到的公式、定理、方法限定在用户当前学段已学范围内。要拔高就单独成块并标注"拓展"。
6. **不编造**：文科类材料取自教材原文或已核实来源；确属自编的，在 header 的 `.src` 里写明"自编题，非原卷"。
7. **配图**：需要图时用内联 SVG，照本文「几何图」与「图形复检」两节执行，**画完必须 `figcheck` 复检**——出题分支同样适用，不因为是自己出的题就免检。

## 出题/判分约定（本项目·数学口径）

- 上海八年级上周末卷，题型：一、选择题；二、填空题；三、解方程；四、解答题（含证明）。
- 一元二次方程部分用得到：配方法、十字相乘、求根公式、判别式 Δ=b²−4ac、韦达定理（x₁+x₂=−b/a，x₁x₂=c/a）。
- 几何部分：全等（SSS/SAS/ASA/AAS/HL）、等腰"三线合一"、线段垂直平分线的判定与性质、直角三角形斜边上的中线等于斜边的一半、三角形中位线定理、三角形外角性质。
- **"只有一个实数根"的分式方程题不要漏解**：既要考虑"去分母后的整式方程有两等根且不是增根"，也要考虑"两根中有一根是增根（x=0 或 x=2）、另一根有效"。
- 证明题里若用到"面积法"（等底等高→面积相等→线段比），比补角平分线定理更贴合初中范围。
- 备选解法尽量避开未学过的高中工具（正弦定理、二倍角公式）；必须用时改写为相似三角形 + 特殊角三角函数值。
- 一题多答的填空（如"22.5° 或 67.5°"）要在答案框里把两个都写出来，并用 note 说明为什么两者都保留。
