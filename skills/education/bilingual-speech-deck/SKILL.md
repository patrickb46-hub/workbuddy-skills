# 中英对照演讲稿 + 英文极简 PPT 生产线

## 何时使用

- 用户给出「调研资料（图片笔记 / docx / 访谈）+ 演讲作业」，要求**一份中英对照演讲稿**和**一份英文 PPT**。
- 典型课题：Then and Now、社区变迁、城市更新、历史街区、城市漫步、Comparative Study。
- 用户强调「PPT 简洁、只留关键词」「多放真实图片」「图表/表格/思维导图」「演讲稿与 PPT 逐页对应」。

## 四条铁律（不可妥协）

1. **图片必须真实**。只用新闻媒体 / 政府 / 机构发布的实拍图片，禁止 AI 生成图、图库水印图、社交平台带 UI 的截图、占位图。每张图在页脚或末页标明来源。
2. **逐页对应**。演讲稿与 PPT 共用一份内容源（`content.py`），一页一节，编号、时间轴、屏幕关键词三处对齐。改稿只改这一处。
3. **PPT 只放关键词**。标题 + 3–5 个词 + 关键数字；完整句子只允许出现在图注（caption）里，且不超过两行。
4. **字号下限（演讲稿 docx，2026-10-28 用户规定）**。见下节，任何情况下不得违反。

## 排版字号（硬性规定 · 演讲稿）

用户 2026-10-28 最终定稿：**正文 12 号**。此前一版曾要求「正文 ≥18、最好 20」，当天即被「演讲稿字体：12」取代——**以 12 为准，不要再退回 18/20**。

| 用途 | 字号 |
|---|---|
| 正文（英文稿 / 中文译） | **12 pt** |
| 章节标题（中文小标题） | **16 pt** |
| 封面主标题 | **22 pt** |
| 出处、图注、页眉、页脚、提示、表头、附录 | **12 pt** |

全文只有 12 / 16 / 22 三档；不再出现 18、20、24、34，也不允许 11 以下的字号。

配套规则：

- **不使用无意义的角标**。不写 `[1]`、`①`、上标数字、`*`、`▸` 之类标记；出处直接写在句末括号或图注里（12 pt），需要时在文末附录集中列一遍。
- 12 号正文很轻，一页会显得空：**用笔记横线补足版面**（`plan()` 会把剩余高度换算成 4–10 行、行距 26 pt 的手写线），不要靠放大字号或拉大行距来填。
- **一页一屏必须自己算**。Word 的行高是 `行距倍数 × 1.2 × 字号`，不是 `行距倍数 × 字号`——按后者估会低估 20%，必溢出。`reference/build_speech_example.py` 的 `plan()` 用 PIL 真实字宽算行数，并打印每页占用率（目标 65–85%）。
- 这一组字号**不适用于 PPT**（PPT 属投影视觉，另有 8.5–38 pt 的层级）。用户未要求前不要改 PPT。

## 工作流

### 1. 读料（不要跳）
- 手写/拍照笔记：先转 JPG 并**转正**（`sips -r 90` 常会转反，270 才对），再用视觉模型逐字转录，保留表格结构与引用标注（`+1` 这类）。
- docx：直接解 `word/document.xml` 取全文；顺手导出 `word/media/` 里的图，确认是不是只是表格截图。
- 已有的 HTML/笔记文件：先读，能复用的事实与来源直接继承，别重复研究。

### 2. 事实核验
- 数字必须落到**权威源**：新华社、央视、人民网、区政府、区志、学术论文。
- 同一条数据出现多个版本时取官方口径，并在出处里写清是哪一家。
- 区分「学生原稿的说法」与「可证实的数据」：像 "more than fifty historic buildings" 这种，要能拆成 `14 处优秀历史建筑 + 37 处保留历史建筑 = 51`，才敢上台讲。

### 3. 取真实图片（关键工序，见 `reference/image-sourcing.md`）
- 境外图库（Wikimedia、Google）在国内网络通常**超时**，不要浪费时间。
- 走两条路：① 直接抓权威媒体的文章页，正则提 `<img>`；② Bing 图片搜索（`cn.bing.com`）解析 `m="{...}"` 里的 `murl` / `purl`，能同时拿到原图地址和来源页。
- 用 `scripts/bing_img.py` 批量下载 + 自动生成对照缩略图，肉眼筛。
- 用 `scripts/grab.py` 抓指定文章页的全部图片链接。
- 筛图标准：能看清主体、无水印、无播放器/点赞等 UI 叠加、分辨率 ≥ 800px 长边、与论点直接相关。

### 4. 定结构（先写 `content.py`）
- 12–15 页：封面 / 地点 / 过去 / 现在 / 变化总表 / 4 个分项变化 / 原因 / 受益者 / 代价 / 反思 / 致谢。
- 每页只回答一个问题；叙事要有转折（"but fame has a bill"）。
- 时长按 150 词/分钟估算：3 分钟≈450 词，5 分钟≈700 词。`content.py` 里给每页标累计时间。

### 5. 做 PPT（`scripts/deck_lib.py` + `reference/build_deck_example.py`）
- 16:9 / 13.333×7.5 in；底色 `#FAF8F5`，正文墨色 `#1C1A17`，强调砖红 `#9C3D2E`，辅助灰绿 `#6E7F6E`，分隔线 `#DED7CB`。
- 字体统一 Helvetica Neue（中文回退 PingFang SC）；标题 31–38pt，正文 12–13pt，图注 8.5pt。
- 版式节奏：左图右文 → 满幅图 → 双图对比 → 表格 → 图表 → 思维导图 → 大字收尾。不要连着三页同一种布局。
- 图片一律**按目标比例裁切**（`photo()` 里用 PIL 裁），禁止拉伸；人像/建筑用 `fx/fy` 控制裁切重心。
- 图表用 matplotlib 生成透明 PNG（`scripts/make_charts.py` 思路），去脊线、去网格竖线、数字直接标在柱端。
- 思维导图用形状画（中心圆 + 四角卡片 + 连线），比贴图清晰、可编辑。
- **每页写 speaker notes**（`note()`），把该页英文稿塞进去——答辩时 PPT 自带提词器。

### 6. 做演讲稿（`reference/build_speech_example.py`）
- A4 竖版，页边距左右 2.0 / 上 2.0 / 下 1.9 cm（版心 17 cm），**一页一屏**：
  `SLIDE 0X / 累计时间`（12pt）→ 中文小标题（24pt）+ 屏幕关键词（12pt）→ 英文正文（**20pt**，行距 1.45）→ 中文译文（**18pt**，浅底色块 + 左侧竖线）→ `提示`（12pt）→ 手写笔记横线。
- 用 `plan()` 自动排版：真实字宽算行数 → 优先 3 行笔记，退到 2 行 / 0 行 → 仍放不下才把英文降到 18pt，并打印占用率。
- 封面 + 全程结构表（页码 / 时间 / 内容 / 关键词，12pt）+ 附录（事实与数据逐条出处、图片来源，12pt）。
- 页脚用 `PAGE` 域出页码；正文里所有数字都要能在附录里查到。
- 生成后必查：`grep '<w:sz w:val'` 是否出现 < 22（即 11pt）的值；`w:vertAlign w:val="superscript"` 必须为 0。

**变体 · 分册/接续稿**（用户只要某几页时，例如「第 10 页及以后单独出一份」）：
- 不复刻封面与结构表，只做一个抬头：`SPEECH SCRIPT · 后半段 · 中英对照` + 中文大标题 + 一行英文副标题（12pt）。
- **不用一页一屏**：节与节之间用一条浅色细线分隔，连续排版、不分页，也不加手写笔记横线；标题、正文、字号与合订本完全一致，便于对照。
- 每节结构不变：`SLIDE 0X / 时间` → 中文小标题 → 屏幕关键词 → 英文 → 中文色块 → 提示。
- 页脚写清册别（如 `后半段（SLIDE 10–14）`），页码重新从 1 起，末行注明接续自哪一页。
- 单独给这份也建桌面软链接；文件名带范围，如 `..._第10页起_中英对照.docx`。

### 7. 自检与交付
- 版式自检无法调用 PowerPoint / Keynote 时（macOS TCC 会报 `privilege violation (-10004)`，`qlmanage` 也会被沙箱拦住），用 `scripts/render_scene.py`：`deck_lib` 会把每次绘制记进 `SCENE`，渲染器用 PIL 按同样坐标重画，逐页出 PNG 拼 contact sheet，专门看**文字溢出 / 压图 / 裁切重心**。
- 用 `QA=1 python3 build_deck.py` 触发渲染。
- 桌面快捷方式：`osascript` 让 Finder 建替身同样会被 TCC 拒绝，改用软链接
  `ln -sfn "<源文件>" "/Users/<user>/Desktop/<文件名>.<ext>"`——Finder 里显示为带箭头的项目，双击可开。

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 图片全黑 / 背景变黑 | 透明 PNG 被转成 RGB | 渲染时用 RGBA 合成到纸色上；PPT 里没问题 |
| 标题压到右侧图片 | 文本框宽度按整行估 | 标题框宽度 ≤ 图文分栏线，或标题换行 |
| 图表标注与数字重叠 | 在数据坐标里手放文字 | 把 "≈4×" 这类注释移进 caption，图上只留数字 |
| 中文行距怪、字挤 | 只设了 `font.name` | 必须同时设 `w:rFonts` 的 `eastAsia` |
| 表格列宽超出版心 | 厘米数与页宽不匹配 | A4 左右各 2.4cm → 版心 16.2cm，列宽合计 ≤ 15.5cm |
| docx 页码对不上 | 只写了固定文字 | 用 `PAGE` 域（`w:fldSimple`） |
| 手机拍的笔记文字倒了 | sips 旋转方向 | 依次试 `-r 90` 与 `-r 270`，看图别猜 |
| 正文 20pt 时某页被挤到第二页 | 用「行距×字号」估高度，少算了 1.2 倍 | 行高 = 行距 × 1.2 × 字号；先减笔记行数，再降行距，最后才降到 18pt |
| 提示/图注还是小字 | 沿用了旧的 8.5/9/10.5 号 | 一律 12pt；全文任何位置不得小于 11pt |
| 出现 `①`、`[1]`、上标数字 | 习惯性做角标 | 删掉；出处写进句末括号（12pt）或文末附录 |

## 需求变更同步（必读）

用户的要求可能后续修改。**任何需求变化都要同时更新三处**：
1. 本文件的「四条铁律 / 排版字号 / 工作流 / 常见坑」；
2. `reference/requirements.md` 的变更记录表（日期 + 变更点 + 影响文件）；
3. 工作区记忆 `.workbuddy/memory/` 当日日志，以及 `MEMORY.md` 里的项目约定。
4. 已交付的文件要不要跟着改，按用户这句话的范围判断（例：说「不用改 ppt」就只重做 docx）。

改动交付物后，记得同步桌面快捷方式指向的文件（软链接本身不用重建，只要路径不变）。
